# RNU4-2 Signature CLI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver an installable renu-score CLI that computes the six-event
signature and LASSO probability using matched controls in an rMATS file.

**Architecture:** Keep model configuration, rMATS parsing, numerical scoring,
and CLI output in four small modules. Parse the file once, retain counts by
event and sample, and center each event on its usable controls. Package the
default TOML as a resource and include a visible example configuration.

**Tech Stack:** Python >=3.11, argparse, TOML, standard numerical/data tools as
useful, hatchling build backend, pytest for development. Scientific Python
libraries are allowed, but no dependency is required merely for its own sake.

**Spec:** docs/superpowers/specs/2026-10-22-renu-cli-design.md

## Global Constraints

- Command renu-score; distribution renu-splicing-signature.
- Default cases group 1, controls group 2; --controls-group can reverse them.
- Default names cases_1, cases_2, etc. and controls_1, controls_2, etc.
- Default intercept -2.927847423; configure in TOML only.
- No --intercept or --print-signature flags.
- Bundle all six exact Table S2 event identities, directions, and weights.
- Missing counts and IJC=SJC=0 are unavailable for that sample only.
- Exclude unavailable controls from the corresponding event baseline.
- Partial signatures retain original weights/intercept without rescaling.
- Required rMATS columns and the GRCh38 requirement must appear in README.
- Flag minimum coverage threshold as a later decision at implementation handoff.
- Git metadata operations require elevated filesystem access. Work in the
  supplied workspace; do not push or publish without authorization.

## Review Focus

- Opposite-strand or different-flank events must never substitute for a selected event.
- Missing control measurements must not bias the baseline toward zero.
- A sample with no events must get NA, rather than an intercept-only probability.
- Swapping groups must also swap generated role-based names and baseline selection.
- Installed execution outside the checkout must find the bundled model.

**Interfaces:**
- model.py produces frozen Event and Model dataclasses, SignatureError,
  `load_model(path: Path | None = None) -> Model`, and a normalized coordinate
  identity shared with the parser. Event exposes id, strand, direction, weight,
  chromosome, and six coordinates; Model exposes name, reference_genome,
  intercept, and events.
- rmats.py produces Counts(ijc, sjc), Sample(name, group, role), Dataset(samples,
  event_counts, warnings), and
  `read_rmats(path: Path, model: Model, controls_group: int = 2,
  group_names: dict[int, list[str]] | None = None) -> Dataset`.
- event_counts maps selected event identities to sample-ordered Counts or
  None. Preserve Counts(0, 0) for coverage reporting; scoring excludes them.

### Task 2: Numerical scoring and per-sample missingness

**Files:**
- Create: src/renu_splicing_signature/scoring.py
- Test: tests/test_scoring.py

**Interfaces:**
- Consumes Model and Dataset from Task 1.
- Produces ScoreResult(rows, details, warnings),
  `score_samples(model: Model, dataset: Dataset) -> ScoreResult`.
- Score rows have sample, group, role, uniform_sum, weighted_sum,
  lasso_linpred, lasso_prob, n_events_used, n_events_expected,
  n_zero_coverage_events, status. Unavailable numeric scores are None.
- Details have one row per expected event per sample, including missing
  events; carry counts where known, baseline where available, contributions,
  and status distinguishing missing counts, zero coverage, and no baseline.

- [ ] **Step 1: Add failing scientific behavior tests.** Use a two-event model
  with directions +1/-1 and weights 2/0.5. For event 1, case (4,0), controls
  (0,4)/(4,4); for event 2, case (0,4), controls (4,0)/(4,4). Independently assert:

  ```python
  assert row.uniform_sum == pytest.approx(3 * math.log(9))
  assert row.weighted_sum == pytest.approx(3.75 * math.log(9))
  assert row.lasso_linpred == pytest.approx(-2.927847423 + 3.75 * math.log(9))
  assert row.lasso_prob == pytest.approx(1 / (1 + math.exp(-row.lasso_linpred)))
  ```

  Add a second case with zero coverage for one event: assert only that case
  loses the event, its count is 1, and its status is partial. Assert zero/NA
  controls are excluded from the mean, single-zero positive-coverage counts
  remain usable, an event with no controls is unavailable, an empty sample
  has None scores, and a run with no usable scores raises SignatureError.
  Include stable probabilities for large positive/negative linear predictors.
- [ ] **Step 2: Run `uv run --python 3.11 --extra dev pytest tests/test_scoring.py -q`.**
  Expected: failures caused by the missing scoring implementation.
- [ ] **Step 3: Implement `score_samples`.** Use log(IJC+0.5)-log(SJC+0.5),
  arithmetic means of each usable control's log ratio, original direction and
  weight, and a stable sigmoid. Preserve absent-event detail rows. Aggregate
  helpful warnings with sample/event identities. Never substitute zero for
  missing data and never return an intercept-only score for empty samples.
- [ ] **Step 4: Run `uv run --python 3.11 --extra dev pytest -q`.**
  Expected: model, parser, and scoring tests all pass.
- [ ] **Step 5: Record task completion and scientific decisions in the ledger.**
